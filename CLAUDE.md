# Разгрузка бэклога

Личный трекер игрового бэклога. Веб-приложение публикуется на GitHub Pages
(https://kissselyochek-byte.github.io/backlog/), Android-приложение — оболочка WebView над этим адресом.
Прогресс хранится в Supabase (таблица `progress`, одна строка на аккаунт, см. `supabase/schema.sql`).

Пользователь пишет по-русски и предпочитает короткие практичные ответы.

## Как менять очередь
Вся очередь — в `queue.json`. После коммита и пуша в `main` Pages обновляется за 1–2 минуты,
приложение подтягивает изменения само при следующем открытии. Пересобирать APK не нужно.

- У каждой игры постоянный `id`. Прогресс привязан к id, поэтому:
  - при замене игры в той же позиции можно оставить id (отметки перейдут на новую игру) — предупреди об этом пользователя;
  - новой игре давай новый уникальный id (например `x-outer-wilds`), никогда не используй id удалённых игр;
  - удаляя игру, просто убирай её объект; номера в списке пересчитываются сами.
- `h` — примерные часы на прохождение, `dev` — устройство: `L` = Legion Go, `S` = Scar 16 (ноутбук).
- `main` у блока — «главное блюдо», открывается после остальных игр блока.
- `bench` — скамейка запасных (только названия).
- Новый бэклог («второй заход»): замени `blocks`/`bench`/`title` целиком на новые с новыми id
  (например с префиксом `b2-`), старый прогресс при этом просто перестанет отображаться.

## Что где
- `index.html` — всё приложение (интерфейс, логика блоков, статистика, вход, синхронизация).
- `config.js` — URL и anon key Supabase (anon key публичный, доступ ограничен RLS).
- `android/` — оболочка APK. Сборка — GitHub Actions (`.github/workflows/android.yml`) при изменениях в `android/`,
  APK выкладывается в релиз `apk`. Подпись — `android/app/backlog.keystore`, не менять, иначе APK не встанет поверх.
